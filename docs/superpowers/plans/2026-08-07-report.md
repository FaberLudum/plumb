# `plumb report` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `plumb report` walks the last N commits and prints, per commit, the three quantities the taxonomy ties to architectural decay — net volume delta, coupling delta, deletion ratio — plus a summary naming the commits where volume and coupling rose together (the decay signature of taxonomy §4.5).

**Architecture:** All computation over already-extracted data is pure and lives in `plumb-core` (`metrics` module: per-commit stats, ratios, the decay-signature rule, text/JSON rendering). `plumb-cli` supplies history: new git helpers (`recent_commits`, `numstat`, and `show_at` generalising `show_at_head`) and a `report_cmd` that computes each commit's coupling delta by diffing cross-module import edges in the files that commit touched, resolved against the **current** `.plumb/architecture.md` — a documented simplification, since the architecture at old commits may have differed. No architecture → coupling reported as `-` and volume still works. This is Tier C instrumentation: no findings, no gate, exit 0 (70 when the run cannot happen).

**Tech Stack:** Rust 1.97, edition 2024. No new dependencies.

## Contract details shared by the tasks

- **Volume delta** of a commit: sum of added minus sum of removed lines over its text files (binary rows in numstat carry `-` and are skipped).
- **Deletion ratio**: removed / added as `f64`; when added is 0, the ratio is reported as `-` in text and `null` in JSON (never a division panic, never `inf`).
- **Coupling edges of one file**: the set of distinct `(from_module, to_module)` pairs where `from_module` is the module owning the file, `to_module` the module an extracted import resolves to, and the two differ. Resolution reuses `plumb_core::boundaries` machinery and the **current** architecture.
- **Coupling delta of a commit**: for each path the commit touched that `boundaries::is_scannable` accepts, edges(child side) minus edges(parent side), summed as a signed count. File absent on one side contributes its edges wholly to the other side's count. First-parent only: `recent_commits` walks `--first-parent`, so a merged PR counts once as its merge diff.
- **Decay signature** (`has_decay_signature`): volume delta > 0 AND coupling delta is `Some(d)` with d > 0. The summary counts and names those commits — this is the §4.5 pattern (volume and coupling rising together), surfaced but never judged: no finding, no exit-code effect.
- **Text output**: one row per commit — short hash (7), `+added`, `-removed`, `ratio` (2 decimals or `-`), `coupling` (`+n`/`-n`/`0`/`-`), subject truncated to 40 — followed by a summary block: totals, mean deletion ratio over commits where it exists, and `decay signature: K of N commits` with the short hashes when K > 0. **JSON output**: an object `{ "commits": [...], "summary": {...} }` with the same fields spelled out (`hash`, `subject`, `added`, `removed`, `deletion_ratio`, `coupling_delta`); serialize with serde like `report.rs` does for findings.

- Produces: `report_cmd::run(repo: &Path, commits: usize, json: bool, output: impl Write) -> Result<()>`.

Behaviour:
- Reads `.plumb/architecture.md` once (optional — absent means every `coupling_delta` is `None`; the report still runs on volume alone; one line on stderr says coupling needs an architecture, printed once, not per commit).
- For each of the last `commits` first-parent commits: volume from `numstat`; coupling delta only when an architecture exists — for each numstat path accepted by `boundaries::is_scannable`, edge sets from the child side (`show_at(hash)`) and parent side (`show_at(hash + "^")`), where a side that is absent or unreadable contributes the empty set; edges via `boundaries::imports` + the same module-resolution the boundary gate uses. plumb-core may need a small pure addition to expose edge extraction — if `boundaries` has no public helper for "distinct cross-module (from, to) pairs of one file", add `pub fn edges(architecture: &Architecture, path: &str, text: &str) -> Vec<(String, String)>` there WITH its own unit test, rather than reimplementing resolution in the CLI.
- Renders with `metrics::render_text`/`render_json` to `output`.
- Flags: `--commits <N>` (default 30), `--json`.
