# npm Ecosystem for the Package-Existence Gate — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `plumb check --diff` blocks on a dependency added to a `package.json` that does not exist on the npm registry — the same Tier A gate (taxonomy §4.1: package hallucination is measured in Python AND JavaScript), second ecosystem.

**Architecture:** `manifest` learns `package.json` (serde_json is already a dependency): the four dependency tables (`dependencies`, `devDependencies`, `peerDependencies`, `optionalDependencies`) all read as name→version maps; a file that does not parse as JSON gets `Gap::Unparseable` exactly like TOML. `Ecosystem` gains `Npm`; the exhaustive matches the codebase deliberately keeps (`deps::added`'s ecosystem hard-coding, `check.rs`'s registry-name match) stop compiling and force every message honest. The registry layer routes by ecosystem: `check.rs` holds one `PyPiRegistry` and one `NpmRegistry` behind a small router implementing the existing `Registry` trait extended to take the ecosystem (`exists(&self, name, ecosystem)`); both concrete registries share the cache file with ecosystem-prefixed keys (`npm:react`, `pypi:ruff` — bare legacy keys read as PyPI so existing caches stay valid). npm lookups hit `https://registry.npmjs.org/{name}` with `@scope/name` URL-encoded as `@scope%2Fname`.

**Tech Stack:** Rust 1.97, edition 2024. No new dependencies (serde_json and ureq already present).

## Contract details

- **Recognition:** the filename `package.json` at any depth, path-only (consistent with `a_manifest_is_recognised_from_its_path_alone`; the empty-body probe must yield a manifest with NO gaps — an empty string is not valid JSON, so the probe path needs the same special-case the TOML probe got: probe with empty text returns `Some(Manifest::default())`-equivalent; read how `parse` handles the pyproject probe and mirror it). Skip `node_modules/` paths entirely: a vendored `package.json` is not this project's manifest (test pins it).
- **Parsing:** the four tables' KEYS are dependency names; values (version ranges) are not validated. Absent tables are fine. A `package.json` that parses but has no tables declares nothing. Non-object tables (e.g. `"dependencies": []`) → `Gap::Unparseable`? No — too blunt: emit the existing `Gap::DependencyGroups`-style precision with a new `Gap::MalformedTable(String)` naming the table; `describe()` says which table and why.
- **Name hygiene:** npm names may contain `@`, `/`, `-`, `_`, `.` and are case-sensitive lowercase. The URL path encodes `/` in scoped names as `%2F`. The existing PyPI name validation (`debug_assert` alphanumeric+`-`) must NOT run against npm names — validation becomes per-ecosystem.
- **Ecosystem routing:** `Registry` trait becomes `fn exists(&self, name: &str, ecosystem: Ecosystem) -> Existence`. The router holds both concrete registries and dispatches. Test stubs update mechanically. `--offline` and the cache semantics apply identically to both.
- **Cache keys:** `npm:<name>` / `pypi:<name>`; a legacy bare key is read as PyPI (test pins a legacy cache file still answering).
- **Blocking message:** `package \`left-pad-typo\` does not exist on npm` — registry name from the exhaustive ecosystem match.
- **Version-check discipline (project convention):** before writing the registry code, confirm the npm registry endpoint shape with a real request OUTSIDE tests (one manual curl in the implementer's shell, quoted in the report): `curl -s -o /dev/null -w "%{http_code}" https://registry.npmjs.org/react` → 200, and a 404 for a garbage name.
