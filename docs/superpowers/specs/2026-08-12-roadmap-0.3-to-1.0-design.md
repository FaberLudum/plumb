# Roadmap 0.3 → 1.0 — design

Date: 2026-08-12
Status: approved by Andrea (brainstorming session, 2026-08-12)

## Goal

Define the release path from v0.2.0 to v1.0 "gold". The guiding decisions,
made explicitly during brainstorming:

1. **1.0 is a balanced mix**, not a single axis: each minor version advances
   one of three axes — engine quality, adoption, evidence — and 1.0 ships
   when all three are at an acceptable level.
2. **Primary quality bar**: the tool must be useful to Andrea and to many
   other developers, and it must not break on the first uncontrolled
   repository it is pointed at. Robustness against wild repositories comes
   *before* distribution — shipping a tool that crashes on its first
   monorepo burns trust permanently.
3. **Distribution**: Claude Code plugin first; the agent-agnostic and
   host-agnostic channel is a git `pre-commit` hook (framework integration
   plus native hook), which covers every agent and every CI host. A GitHub
   Action is a thin wrapper over that, not the foundation.
4. **Tree-sitter/AST only if the evidence demands it.** Regex scanning
   stays until replay or corpus calibration shows real false positives or
   negatives that regex cannot fix. Engineering follows measurement.
5. **Evidence axis ships pre-1.0 in full**: human-repo control replay,
   live phase-6 on the Umarell repositories, and the process-layer
   evidence sweep.
6. **New languages and ecosystems only with a pilot repository** to
   calibrate against, as Umarell served for C# and Dart. No coverage
   theatre. External contributors can bring their own; CONTRIBUTING
   already carries the recipes.
7. **Multi-repo coherence is in scope** (added 2026-08-12, same day —
   first concrete external demand signal). The use case, from a request
   Andrea received at work: a fleet of microservices in single repos,
   built over years by different people, where old services carry old
   conventions and new services carry the current, better standard. The
   ask: keep the whole fleet on the new standard. Plumb's existing
   design already fits the hard half — diff-aware gates block only NEW
   violations, so an old repo can adopt the shared standard without its
   existing debt blocking anyone, while decay stops from that moment (a
   ratchet). What is missing is the sharing mechanism (`extends`,
   0.5) and fleet-level visibility (`plumb fleet`, 0.8). Honest scope
   limit, to be stated in docs: Plumb governs declared architecture,
   dependencies, boundaries and agent instructions — not style or
   framework technique, which stay delegated to linters (Hygiene tier)
   per taxonomy §5.

## Context: what the competitive scan found (2026-08-12)

No tool does Plumb's combination. Per piece: boundary gates have mature
single-language competitors (import-linter, ArchUnit, dependency-cruiser,
eslint-plugin-boundaries; Axivion commercially); the hallucinated-package
gate is commoditising fast (Socket, Snyk, Aikido, dedicated OSS scanners);
the adapter layer is partially eroded by the AGENTS.md standard
convergence, but generation-from-artefacts plus the drift gate remain
unique; no tool measures longitudinal coupling with executable gates; no
tool grades rules by published evidence. The defensible core is the
multi-language diff-aware boundary gate, the drift gate, and the
taxonomy-plus-calibration method. The window is open now: the problem is
freshly recognised, the funded players have not assembled the combination.

## The versions

Each version is one axis. Scope per version is deliberately small enough
to ship; anything not listed is out of that version's scope.

### 0.3 — Clean engine (axis: engine)

- `check --repo`: whole-repository scan. Serves two audiences measured
  during replay: the adoption first run ("what already crosses
  boundaries") and CI checkouts where `--diff` sees nothing.
- Factor out the four near-identical registry structs (third use is
  past; the rule fires).
- Replay-surfaced polish: index-stale findings drown the signal
  (43–79% of emissions in replay); `report` over-claims commit count
  when history runs out; the coupling column cannot distinguish
  "inert" from "no change".
- Fix `init --defaults` missing `lib/` on the standard Flutter layout.

Exit: all four items landed, gates green, replay spot-check on Umarell
shows the noise reductions.

### 0.4 — Wild-repository robustness (axis: engine)

The version that answers the primary quality bar directly. Current
calibration is two repositories by one author in one AI-driven style;
zero false positives there promises nothing about strangers' code.

- **Corpus harness**: a script that clones N (target 50+) public
  repositories across the five supported languages and varied layouts —
  monorepos, workspaces, generated code, vendored trees — and runs
  `check`, `init`, and `report` on each, asserting: no panic, no absurd
  output, sane wall-clock. Findings triaged by sampling.
- Manifest fuzzing: malformed TOML/JSON/XML/YAML inputs must degrade to
  `Gap`s, never crash.
- Explicit limits: file-size cap, scan timeout, non-UTF-8 paths and
  content, BOM handling (already bitten once), symlink behaviour.
- Graceful degradation as a rule: a repository Plumb cannot understand
  produces a finding or a gap, never a panic and never a wall of false
  positives.

Exit bar: zero crashes on the whole corpus; sampled findings triaged
with false positives fixed or documented as known limits in gates.md.
Every breakage found becomes a regression test.

### 0.5 — Onboarding and org adoption (axis: adoption)

- `init --from-code`: AI drafts `.plumb/` (architecture, conventions,
  invariants) from the existing code; the human reviews as architect.
  Kills the "I have to write architecture.md by hand" friction that
  blocks cold adoption. Also serves the fleet use case: distil the
  shared standard from the organisation's best repositories.
- `extends`: a repository's `.plumb/` declares a shared source (local
  path or git repository); shared conventions, invariants and
  boundaries merge with the local artefacts. Precedence rules (does
  local override, and on which artefact kinds) are decided at planning
  time. Remote fetch lives in `plumb-cli` (network boundary respected);
  the fetched source is cached and committed so CI stays
  offline-capable. The existing drift gate extends naturally: stale
  generated files against the shared source fail the gate.
- Quickstart rewritten around the new flow.

### 0.6 — Distribution (axis: adoption)

- Claude Code plugin: skill plus hook packaging, marketplace listing.
  Primary channel — the audience is pre-selected.
- `pre-commit` integration (framework hook plus native git hook):
  agent-agnostic and host-agnostic; covers GitLab, Azure DevOps,
  Jenkins and every agent.
- GitHub Action as a thin wrapper over the CLI.
- `cargo install` via crates.io as the hygienic baseline.

### 0.7 — Human-repository control (axis: evidence)

- Retrospective replay on a human-only repository as the control group;
  partially closes success criterion 3.
- Conditional slot: if corpus (0.4) or this replay shows regex-caused
  false results, tree-sitter enters the roadmap here — targeted at the
  failing languages only. Otherwise the slot stays empty.

### 0.8 — Live phase 6 and fleet visibility (axis: evidence)

- Plumb in the daily Umarell workflow. Requires Andrea's decision on
  `.plumb/` coexistence with the hand-written CLAUDE.md files there.
- Real-usage measurements; friction found feeds fixes.
- `plumb fleet`: aggregate the checks of N repositories sharing a
  standard (via `extends`) into one report — which repositories
  deviate, where, and the convergence trend over time. The measurement
  half of the multi-repo use case; enforcement (per-repo CI gates)
  already works from 0.5.

### 0.9 — Process layer and hardening (axes: evidence + engine)

- Process-layer evidence sweep: what the literature actually says about
  TDD, plan-first, and review efficacy with AI agents. New taxonomy rows;
  any resulting checks enter at the tier their evidence supports. Same
  rule as ever: no source, no rule.
- SAST delegation (the remainder of phase 5).
- Contract freeze: CLI surface, exit codes, output format, configuration.
- Security review; documentation completeness pass; semver policy
  written down.

### 1.0 — Gold

- Contracts stable under semver.
- Success criteria measured and documented (including the control-group
  result from 0.7).
- All four channels live.
- Perimeter declared: five languages, four ecosystems, community recipes
  for extension.

## Transversal rules (not versions)

- A new language or ecosystem lands only with a pilot repository to
  calibrate against.
- Tree-sitter/AST only when replay or corpus evidence demands it.
- Every new feature passes replay or corpus calibration before it is
  called done.
- Ordering logic of the whole roadmap: robust → easy → distributed →
  proven. Robustness (0.4) lands before strangers get the tool (0.6);
  evidence phases (0.7–0.9) run with a distributable tool in hand so
  external feedback can arrive during them.

## Out of scope pre-1.0

- Java, Go, PHP or any further language/ecosystem without a pilot repo.
- External process plugins (rejected in the plugin-seams design: a
  supply-chain gate must not execute PATH binaries).
- Function-length, complexity, or readability checks (taxonomy §5:
  documented non-defects).
